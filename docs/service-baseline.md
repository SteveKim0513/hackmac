# 서비스 기준 (Service Baseline)

HackMac에서 앱이 "서비스"가 되려면 지켜야 하는 기본 요건이다. 함수 하나가 도는 것과 서비스의 차이는 이것이다:

- **함수**: 요구한 것을 한 번 해낸다. 설정이 바뀌면 코드를 고쳐야 하고, 실패하면 아무 일도 안 일어난 것처럼 보인다.
- **서비스**: 처음 쓰는 사람이 안내를 받고, 자기 상황에 맞게 조정하고, 잘 될 때와 안 될 때 모두 무슨 일이 일어났는지 알 수 있고, 매일 켜 둬도 믿을 수 있다.

기준은 열 가지다. 코드가 직접 확인할 수 있는 것은 **검증 게이트**(`modules/build/gate.ts`)가, 읽고 판단해야 하는 것은 **감사 담당**(`resources/agent/roles/auditor.md`, 만든 쪽과 다른 회사의 엔진)이 본다. 하나라도 어긋나면 설치되지 않는다.

| # | 기준 | 한 줄 설명 | 확인 |
|---|---|---|---|
| S1 | 목표 충족 | 기획에서 확정한 요구사항(R1, R2 …)이 하나도 빠짐없이 구현돼 있다 | 게이트(요구사항마다 시험) + 감사(근거를 코드에서 찾아 적는다) |
| S2 | 조정 가능 | 사람마다 다를 수 있는 값(시각·횟수·이름·주소·분량·켜기 끄기)은 코드 상수가 아니라 `settings`로 선언하고, 앱 상세의 설정 화면에서 바꾼다. 기본값은 바로 써도 되는 값이다 | 게이트(선언한 설정을 스크립트가 읽는다 · 읽는 설정은 선언돼 있다) + 감사(코드에 박힌 값이 없다) |
| S3 | 첫 사용 준비 | 쓰기 전에 필요한 것(권한 승인, 필수 설정)을 사용자가 알 수 있다. 필수 설정이 비어 있으면 조용히 실패하지 않고 "설정에서 ○○을 정해 주세요"라고 알린다 | 감사 |
| S4 | 결과가 보인다 | 실행할 때마다 사용자가 결과를 본다: 잘 됐을 때, 할 일이 없을 때, 안 됐을 때 모두. 아무 일도 안 일어난 것처럼 끝나는 길이 없다 | 감사 |
| S5 | 실패를 안다 | 외부 호출(인터넷, 다른 앱 자동화)이 실패하거나 빈 결과일 때 이유를 쉬운 말로 알리고 로그에 남긴다. 이 실패 경로를 시험하는 파일(`checks/E*-*.sh`)이 있다 | 게이트(외부 접속·자동화가 있으면 오류 시험 필수) + 감사 |
| S6 | 다시 해도 안전 | 같은 단축키를 두 번 눌러도, 중간에 끊겨도 데이터가 꼬이거나 사라지지 않는다. 되돌릴 수 없는 일은 먼저 확인을 받는다. 파일은 `$HACKMAC_DATA_DIR` 안에만 쓴다 | 감사(이식성은 게이트) |
| S7 | 기록이 남는다 | 판단 지점마다 `echo`(AppleScript는 `log`)로 남겨서, 나중에 "무엇을 하다가" 실패했는지 실행 로그로 알 수 있다 | 게이트(스크립트마다 기록 줄이 있다) |
| S8 | 설명이 있다 | 스토어 카피(tagline·usage)가 쉬운 말로 쓰였고, 설정이 있는 앱이면 "앱 상세의 설정에서 바꿀 수 있다"는 것과 처음 쓸 때 뜨는 권한 창을 usage에 안내한다 | 카피 담당이 쓰고 감사가 확인 |
| S9 | 이식성·안전 | 다른 맥에서도 돈다(홈 절대경로·외부 도구 없음), 권한 선언이 실제와 같다, 대화창은 HackMac 팝업으로 | 게이트(이미 있음) |
| S10 | 고칠 수 있다 | 앱을 다시 열어 수정할 수 있고, 수정하면 버전이 올라가며 기존 요구사항도 다시 확인한다 | 게이트(버전) + 감사(요구사항 전체 재확인) |

## 함수 수준과 서비스 수준의 예

요구: "단축키를 누르면 오늘 일정을 알림으로 보여 준다. 알림 시각을 조정할 수 있다."

- 함수 수준: `show.sh` 하나가 일정을 읽어 알림을 띄운다. 시각은 스크립트에 `09:00`으로 박혀 있다. 캘린더가 비면 아무것도 안 뜬다. 권한 창이 뜨는지 안내가 없다.
- 서비스 수준: 설정에 "알림 시각"(기본 09:00)이 있어 앱 상세에서 바꾼다(S2). 일정이 없으면 "오늘은 일정이 없어요"가 뜨고(S4), 캘린더를 못 읽으면 "캘린더 접근을 허용해 주세요"가 뜬다(S3·S5). 읽기 실패를 흉내 낸 시험이 있다(S5). usage에 처음 쓸 때 권한 창이 뜬다는 안내와 설정 위치가 있다(S8).

## 구현 위치

- 게이트가 보는 것: `modules/build/gate.ts`의 `baseline` 검사 (S2 선언↔사용, S5 오류 시험, S7 기록 줄).
- 감사가 보는 것: `modules/build/audit.ts` — 요구사항 전체와 이 기준을 앱 파일에 대어 항목마다 `충족 / 미충족 + 근거(파일과 하는 일)`를 낸다. 감사가 못 읽거나 하나라도 미충족이면 설치하지 않고 어긋난 점을 개발 담당에게 돌려준다.
- 사용자에게는 설치 직전에 항목별 확인표(✓와 근거)로 보인다.
- 설정 화면: 앱 상세의 "설정"(`src/detail/AppSettings.tsx`). 선언한 `settings`·`secrets`가 그대로 입력칸이 된다.
